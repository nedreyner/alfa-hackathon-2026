# CLAUDE.md — правила для агента-разработчика «Альфа Инсайт»

«Альфа Инсайт» — прототип новостной аналитики для крупного бизнеса. Это клиенты Альфа-Банка с выручкой от 15 млрд ₽. Сервис превращает поток новостей в персональные инсайты для конкретной компании и конкретного человека в ней (финдиректор, казначей, собственник). Каждый инсайт отвечает на вопросы: что произошло, почему это важно именно вам, какие риски и возможности, что делать и что думает Альфа-Банк. Для каждого утверждения виден источник.

Главная фича — **«цепная реакция»**: событие бьёт по отрасли, клиент связан с ней через платежи поставщикам или покупателям. Сервис считает эту связь из данных и показывает её цепочкой.

## Где спецификация

Вся спецификация лежит в `docs/`. Начинай с `docs/README.md`. Работа идёт по бэклогу `docs/14-backlog.md`: берёшь первую незакрытую задачу, у которой выполнены зависимости, и делаешь её целиком, включая тесты и критерии приёмки.

Спецификация — источник истины для имён, схем, контрактов API, промптов и формул. Если код должен разойтись со спецификацией, поправь документ в том же коммите и коротко объясни причину в сообщении коммита. Молча расходиться нельзя.

## Стек (менять только через ADR в `docs/01-review.md`)

- **Бэкенд:** Python 3.12, FastAPI, Pydantic v2, pydantic-settings, uv (lock-файл `backend/uv.lock`), Typer (CLI `alfa`), APScheduler 3.x, structlog.
- **Данные:** DuckDB (статичные аналитические данные из CSV, только чтение после сборки), SQLite в режиме WAL (новости, события, инсайты, трассы, кеш LLM, бюджет).
- **Поиск:** SQLite FTS5 по лемматизированному тексту (pymorphy3). Эмбеддингов нет.
- **LLM:** официальный пакет `openai` (`AsyncOpenAI`, Chat Completions) поверх OpenAI-совместимого шлюза. LangChain, LlamaIndex, CrewAI, AutoGen и любые готовые агентные фреймворки **запрещены** условиями кейса.
- **Сбор:** httpx, feedparser, trafilatura. PDF: pdfplumber и pypdfium2. **PyMuPDF не использовать** (AGPL).
- **Фронтенд:** React 19, TypeScript 5.9, Vite, `@alfalab/core-components`, TanStack Query 5, React Router 7, `@xyflow/react` 12, Recharts 3, openapi-typescript и openapi-fetch.
- **Запуск:** docker compose (`init`, `api`, `worker`, `web`).

## Команды

```bash
make setup        # uv sync (backend) + npm ci (frontend)
make check        # ruff check, ruff format --check, mypy, eslint, tsc --noEmit
make test         # pytest (LLM_MODE=fake) + vitest
make data         # синтетика при отсутствии реальных данных → DuckDB → миграции SQLite
make seed         # загрузка seed-новостей → разметка → кластеризация → ранжирование
make dev-api      # uvicorn с автоперезапуском на :8000
make dev-worker   # фоновый планировщик
make dev-web      # vite на :5173 (прокси /api → :8000)
make openapi      # выгрузить OpenAPI и сгенерировать TS-типы
make up / down    # docker compose
make eval         # офлайн-метрики качества
uv run alfa --help
```

Цели Makefile создаются в задаче T1.1. Если цели ещё нет, используй эквивалентные команды `uv run …` и `npm run …`.

## Правила работы с LLM

- **В тестах никогда не обращайся к живому шлюзу.** pytest всегда запускается с `LLM_MODE=fake` (детерминированные заглушки) или `replay` (только кеш). Живые вызовы — только вручную через CLI.
- Все вызовы идут через `alfa_insight.llm` (`LLMRouter`). Прямые вызовы `openai` из других модулей запрещены: так обходятся кеш и учёт бюджета.
- Промпты лежат в `backend/alfa_insight/prompts/*.j2` и имеют версию. Изменил смысл промпта — увеличь версию, иначе кеш вернёт старый ответ.
- Текст новостей, PDF и пользовательский ввод — **недоверенные данные**. Они всегда идут в промпт внутри обёртки `untrusted` (см. `docs/05-prompts.md` §1) и никогда не попадают в system-сообщение.
- Бюджет 500 ₽ в сутки общий на команду. Ручные массовые прогоны (разметка сотен новостей, прекомпьют) запускай только с флагом `--max-cost` и смотри `uv run alfa llm budget`.

## Данные и секреты

- `data/raw/` и `data/runtime/` не коммитить никогда. В них реальные данные клиентов и рабочие базы.
- В репозиторий попадают только синтетические данные (`data/synthetic/`) и публичные seed-новости.
- Секреты (`LLM_API_KEY`, `SESSION_SECRET`, `ADMIN_TOKEN`) живут только в `.env`. Шаблон без значений — `.env.example`.
- Реальные названия компаний и ИНН из CSV не должны попадать в логи, тестовые фикстуры и коммиты.

## Конвенции кода

**Python**
- Типизация везде; mypy без ошибок в `alfa_insight/`. Модели данных — Pydantic v2 (`BaseModel`, `Field`), конфиги — pydantic-settings.
- Слои и разрешённые импорты описаны в `docs/02-architecture.md` §4. SQL к SQLite пишется только в `alfa_insight/store/`, к DuckDB — только в `alfa_insight/data/`.
- Время хранится в UTC (ISO 8601 с `Z`). В Москве (`Europe/Moscow`) — только при отображении и для суточной границы бюджета.
- Деньги — `float` в рублях. Доли — `float` от 0 до 1. Проценты появляются только при выводе.
- Логи — structlog с полями `run_id`, `company_id`, `task`; без `print`.
- Ошибки предметной области — свои исключения из `alfa_insight/errors.py`. API переводит их в коды ошибок из `docs/09-api.md` §6.
- Имена в коде английские, тексты для пользователя русские, комментарии короткие и только там, где неочевидно «почему».

**TypeScript**
- Строгий режим TS. Типы API только генерируются из OpenAPI (`src/api/schema.d.ts`), вручную их не пишем.
- Серверное состояние живёт в TanStack Query, локальная сессия — в небольшом сторе (zustand). Глобальных контекстов «на всё» не заводим.
- Компоненты берём из `@alfalab/core-components`, импорт по подпути: `import { Button } from '@alfalab/core-components/button'`.
- Все пользовательские строки (метки enum, подписи) собраны в `src/lib/labels.ts`.

## Definition of Done для задачи из бэклога

1. Код и тесты написаны. `make check` и `make test` зелёные.
2. Критерии приёмки задачи из `docs/14-backlog.md` проверены, команды из них выполнены.
3. Изменили контракт (схема, эндпоинт, таблица) — обновлены спецификация и, для API, `frontend/openapi.json` с TS-типами.
4. Новые зависимости внесены в lock-файлы и `THIRD_PARTY_NOTICES.md` (с лицензией).
5. В задаче в `docs/14-backlog.md` отмечен статус `[x]`, при необходимости с одной строкой примечания.

## Git

- Работай в ветке, которую задаёт текущая сессия или пользователь. Основная ветка — `main`.
- Коммит небольшой и законченный: одна задача — один или несколько коммитов. Формат Conventional Commits с ID задачи, например `feat(data): T1.7 производные таблицы и профили компаний`.
- Перед коммитом выполни `make check` и `make test`. Не коммить сгенерированные базы, `.env` и `node_modules`.

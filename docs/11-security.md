# 11. Безопасность

Прототип реализует меры ниже в коде. Остальное описано в README в разделе «Безопасность» (§12).

## 1. Модель угроз

| Актив | Угроза | Мера (раздел) |
|---|---|---|
| Ключ LLM-шлюза и бюджет | Утечка ключа; выжигание бюджета запросами | §6, §8 |
| Данные компаний (CSV) | Утечка в git, логи, другой компании | §2, §7 |
| Инфраструктура хоста | SSRF через «проверить ссылку» | §3 |
| Поведение агента | Промпт-инъекция в новостях, PDF и вводе пользователя | §4, §5 |
| Доверие к выводам | Галлюцинации, подмена источников, чужие ссылки в ответе | `08-agent.md` §9, §9 здесь |
| Пользователь | Навязанные действия от имени банка | §10 |

Границы доверия:
- **Доверенное:** код, конфиги, справочники, данные из CSV после сборки.
- **Недоверенное:** тексты новостей, PDF, URL и текст от пользователя, ответы LLM. Ответы LLM проходят валидацию схемой и проверку.

## 2. Аутентификация и изоляция данных компании

- Сессия — подписанная cookie (`09-api.md` §2). Подделка или порча → `401`. Секрет — `SESSION_SECRET` (не короче 32 байт). Если `DEMO_MODE=false`, а секрет пуст или равен значению из `.env.example`, API не стартует.
- `company_id` берётся **только из сессии**. В DTO запросов поля `company_id` нет нигде, кроме `POST /api/session`.
- Объекты проверяются на принадлежность компании: инсайт, прогон, трасса, чат, приватное событие, источники `client_data` и `user_input` (`sources.company_id`). Чужой объект → `404`.
- Инструменты агента получают компанию из `AgentContext`. В аргументах инструментов её нет (ADR-23). `allowed_event_ids` не даёт модели обратиться к приватным событиям других компаний.
- Режим жюри (`jury=true`) позволяет войти в любую целевую компанию, но в каждый момент сессия видит одну компанию.

## 3. SSRF: безопасный загрузчик (`net/safe_fetch.py`)

```python
class FetchResult(BaseModel):
    url_final: str; status: int; content_type: str; text: str; bytes: int; elapsed_ms: int

async def safe_fetch(url: str, *, max_bytes: int = 2_000_000, timeout_s: float = 10.0,
                     max_redirects: int = 3) -> FetchResult: ...
```

Правила (нарушение → `BlockedUrl` → `400 blocked_url` или `run.failed`):

1. Схема только `http` или `https`. Порт только 80 или 443 (или не указан). Без логина и пароля в URL. Длина URL ≤ 2048.
2. Хост не IP-литерал из запрещённых сетей и не `localhost`, `*.local`, `*.internal`, `*.localhost`, `metadata.*`.
3. DNS-разрешение (`loop.getaddrinfo`). **Все** адреса должны быть публичными: `ipaddress.ip_address(a).is_global` и при этом не private, loopback, link-local, multicast, reserved, unspecified. Отдельно запрещены `100.64.0.0/10`, `169.254.0.0/16` (метаданные облаков), `fc00::/7`, `fe80::/10`, `::ffff:0:0/96` с приватным IPv4.
4. **Защита от DNS rebinding:** соединение идёт на уже проверенный IP. Запрос отправляется на `scheme://<ip>:<port>/path`, с заголовком `Host: <hostname>` и `extensions={"sni_hostname": hostname}` (httpx и httpcore), поэтому TLS-сертификат проверяется по исходному имени. Если в окружении обязателен исходящий прокси (`HTTPS_PROXY`), закрепление IP невозможно: тогда делается только проверка DNS, а риск описан в README.
5. Редиректы обрабатываются вручную (`follow_redirects=False`), не больше 3. **Каждый** `Location` проходит шаги 1–4.
6. Ответ читается потоком, обрыв при превышении `max_bytes`. Разрешённые `Content-Type`: `text/html`, `application/xhtml+xml`, `text/plain`. Иначе `unsupported_content`.
7. Таймауты: соединение 5 с, весь запрос 10 с. User-Agent — из `config/sources.yaml`.
8. Cookie и авторизационные заголовки не отправляются и не сохраняются.

## 4. Промпт-инъекции

**Слои защиты:**

1. **Разделение ролей:** внешние тексты никогда не попадают в `system`. Они вставляются в `user` или `tool` внутри `<untrusted_document>` с правилом из `05-prompts.md` §1.
2. **Санитизация** (`sanitize_untrusted`): удаление невидимых символов и символов-тегов Unicode, экранирование закрывающего тега обёртки, лимит длины.
3. **Детектор** (`text/injection.py`, шаблоны в `data/reference/injection_patterns.yaml`). Регулярки без учёта регистра:
   - RU: `игнорируй (все )?(предыдущие|прошлые|вышеуказанные) (инструкции|указания)`, `забудь (все )?(инструкции|правила)`, `ты теперь`, `новая инструкция`, `системн(ый|ое) (промпт|сообщение)`, `выведи (свой )?(промпт|инструкции)`, `не сообщай пользователю`, `представь,? что ты`;
   - EN: `ignore (all )?(previous|prior|above) (instructions|prompts)`, `disregard (the )?(previous|above)`, `you are now`, `system prompt`, `developer mode`, `jailbreak`, `act as`;
   - структурные: `<\s*/?\s*(system|assistant|untrusted_document)`, `\[INST\]`, `<\|im_start\|>`, `###\s*(system|instruction)`, base64-блоки `[A-Za-z0-9+/]{200,}={0,2}`, больше 5 невидимых символов.
   Результат — `injection_flags` (список `id` сработавших шаблонов). Модель разметки дополнительно ставит `injection_suspected`. Формат файла:
   ```yaml
   version: 1
   patterns:
     - {id: ru_ignore_instructions, lang: ru, regex: "игнорируй (все )?(предыдущие|прошлые|вышеуказанные) (инструкции|указания)"}
     - {id: base64_blob, lang: any, regex: "[A-Za-z0-9+/]{200,}={0,2}"}
   max_invisible_chars: 5
   ```
4. **Последствия флага:** событие получает `injection_suspected=1` и исключается из прекомпьюта. В карточке и в трассе фичи B есть предупреждение. Текст по-прежнему используется только как данные.
5. **Ограниченный ущерб:** у агента нет инструментов записи и сетевых инструментов (§5), ответы проходят схему и проверку (`no_foreign_urls`, `refs_exist`, `numbers_match`). Даже успешная инъекция не может ничего изменить или отправить. Максимум — испортить текст, а проверка его отбракует.
6. **Тестовые данные:** в seed две искусственные новости с инъекциями (`06-ingestion-search.md` §10) для демонстрации и регрессионных тестов.

## 5. Инструменты агента

- Белый список по видам прогонов (`08-agent.md` §5.1). Все инструменты **только читают** локальные данные (SQLite и DuckDB). Сетевых инструментов у модели нет: загрузку URL делает система до запуска агента.
- Аргументы проходят Pydantic-валидацию с границами (длина запроса, лимиты, перечисления), `industry_id` и `factor_id` сверяются со справочником.
- Лимиты: не больше 8 вызовов за прогон, таймаут 10 с на инструмент, результат не длиннее 6000 символов.
- Каждый вызов логируется в `trace_events` (`tool.call` и `tool.result` с аргументами). Это журнал аудита.
- Действие «оставить заявку» агенту недоступно (§10).

## 6. Секреты

- `LLM_API_KEY`, `SESSION_SECRET`, `ADMIN_TOKEN`, `JURY_CODE` — только в переменных окружения (`.env`, в `.gitignore`). В репозитории лежит `.env.example` без значений.
- Ключ шлюза используется только на сервере (`llm/client.py`). Фронтенд его никогда не получает. Заголовки запросов к шлюзу не логируются.
- В CI секретов нет: тесты идут с `LLM_MODE=fake`.
- Перед первым публичным коммитом включается сканирование секретов (GitHub secret scanning или `gitleaks` в CI).

## 7. Данные и приватность

- Реальные CSV и PDF лежат только в `data/raw/`, рабочие базы — в `data/runtime/`. Оба каталога в `.gitignore`. В git — только синтетика и публичные фрагменты новостей.
- В логах есть `company_id`, но нет названий, ИНН и сумм реальных компаний.
- **Индивидуальные предприниматели среди контрагентов:** ИНН из 12 цифр или название, начинающееся с «ИП», — это персональные данные. В выдаче (`top_counterparties`, инструменты, UI, промпты) название заменяется на «ИП (контрагент)», а в DuckDB — на этапе сборки, в `counterparty_industry.name`.
- Трассы, источники `client_data` и чат видит только своя компания.
- Ответы шлюзу содержат профиль компании. Это допустимо в рамках хакатона, но в README сказано, какие данные уходят в LLM: профиль без ИНН, доли и названия крупнейших контрагентов.

## 8. Злоупотребления и бюджет

- Лимиты частоты по сессии (`09-api.md` §7), суточный лимит фичи B на сессию, ограничение одновременных прогонов.
- Бюджет: суточный лимит, резерв под интерактив, лимит на прогон (`04-llm.md` §7). Фоновые задачи останавливаются раньше интерактивных.
- Размеры входа: URL ≤ 2048, текст ≤ 20 000 символов, вопрос в чат ≤ 1000 символов, тело запроса ≤ 64 КБ (`client_max_body_size` в nginx и проверка в FastAPI).

## 9. Вывод пользователю

- Фронтенд рендерит тексты LLM только как текст: никакого `dangerouslySetInnerHTML` и HTML или Markdown из ответов модели.
- Внешние ссылки — только из `sources.url` (проверка `no_foreign_urls`), с `target="_blank" rel="noopener noreferrer"`.
- Метки `fact`, `bank` и `ai` видны всегда. Плашки `needs_review`, `stale` и `injection_suspected` не скрываются.

## 10. Действия от имени пользователя

- Единственное «действие» — заявка на продукт. Это **имитация**: запись в `leads`, без внешних вызовов. Требуется явное подтверждение в модальном окне (`confirm: true` в API), текст «Демо: в реальном сервисе с вами свяжется менеджер».
- Агент не может создавать заявки. Он только предлагает продукт из каталога (ADR-16).

## 11. HTTP-заголовки и транспорт (nginx)

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
                         connect-src 'self'; font-src 'self' data:; frame-ancestors 'none'; base-uri 'self'; form-action 'self'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
Strict-Transport-Security: max-age=31536000   (только за HTTPS)
```

`'unsafe-inline'` для стилей нужен xyflow и core-components (inline-стили). Скрипты только свои. CORS не нужен: SPA и API на одном origin. В разработке работает прокси Vite.

## 12. Зависимости

- Версии зафиксированы lock-файлами (`uv.lock`, `package-lock.json`). Установка: `uv sync --frozen`, `npm ci`.
- Новая зависимость → лицензия проверяется и вносится в `THIRD_PARTY_NOTICES.md`. Лицензии AGPL и GPL в рантайме не используются (ADR-12).
- В Docker-образах процессы работают от непривилегированного пользователя, файловая система только на чтение, кроме `data/runtime`.

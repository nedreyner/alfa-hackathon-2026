# Спецификация «Альфа Инсайт»

Пакет документов для агента-разработчика. Цель: по спецификации остаётся только написать код. Архитектура, схемы данных, контракты, формулы, промпты и критерии приёмки уже определены.

1. [01-review.md](01-review.md) — разбор исходного плана: что оставляем, что исправляем, принятые решения (ADR).
2. [02-architecture.md](02-architecture.md) — компоненты, процессы, потоки данных, кто с кем и как взаимодействует.
3. [03-data.md](03-data.md) — CSV-контракт и маппинг колонок, справочники, DuckDB, полная DDL SQLite, профиль компании.
4. [04-llm.md](04-llm.md) — шлюз, распределение моделей по задачам, структурированный вывод, кеш, бюджет.
5. [05-prompts.md](05-prompts.md) — тексты всех промптов.
6. [06-ingestion-search.md](06-ingestion-search.md) — RSS, извлечение текста, префильтр, дедупликация, разметка, кластеризация, PDF, ЦБ, поиск BM25.
7. [07-ranking.md](07-ranking.md) — скоринг, «цепная реакция», роли, пример расчёта.

10. [10-frontend.md](10-frontend.md) — экраны, компоненты, дизайн, работа с API.
11. [11-security.md](11-security.md) — модель угроз и меры.
12. [12-quality.md](12-quality.md) — офлайн- и онлайн-метрики, разметка, отчёты.
13. [13-deploy-demo.md](13-deploy-demo.md) — Docker, хостинг, CI, сценарий демо, чеклист сдачи.

## Глоссарий

| Термин | Значение |
|---|---|
| Целевая компания | Компания из CSV с выручкой ≥ 15 млрд ₽ (настраивается `TARGET_REVENUE_RUB`). Для них считаются профили и ранжирование |
| Демо-компании | 6 компаний из `config/demo.yaml` с продуманными «историями». Для них инсайты считаются заранее |
| Отрасль (`industry_id`) | Элемент собственной таксономии из 43 отраслей, привязанной к префиксам ОКВЭД-2 (`data/reference/industries.yaml`) |
| Фактор (`factor_id`) | Макрофактор риска: ключевая ставка, курсы валют, санкции, логистика и т. д. (`data/reference/factors.yaml`) |
| Эффект (`effect`) | Как событие влияет на отрасль: `prices_up`, `demand_down`, `supply_down` и т. д. (`docs/03-data.md` §5.3) |
| Новость (`news`) | Одна статья из одного источника |
| Событие (`event`) | Кластер новостей об одном и том же факте из разных источников. Инсайт строится на событие, а не на статью |
| Канал (`channel`) | Путь, по которому событие доходит до компании: `own` (своя отрасль), `supply` (поставщики), `demand` (покупатели), `factor` (макрофактор) |
| Путь влияния (`chain path`) | Конкретная цепочка «событие → отрасль/фактор → доля в платежах/признак компании → риск/возможность» с числовым вкладом |
| Экспозиция | Насколько компания зависит от отрасли или фактора: доля платежей, признаки продуктов и ВЭД |
| Покрытие (`coverage`) | Доля объёма платежей компании, для которой известна отрасль контрагента |
| Инсайт | Персональный структурированный разбор события для компании (`docs/08-agent.md` §8) |
| Утверждение (`claim`) | Одно предложение инсайта с меткой `fact`, `bank` или `ai` и ссылками на источники |
| Evidence | Фрагмент доказательной базы, полученный инструментом агента. Внутри прогона у него короткий id `E1`, `E2`, …, в хранилище — постоянный `source_id` |
| Run | Один прогон агента (генерация инсайта, анализ новости, ответ в чате). У него есть статус и трасса |
| Трасса | Упорядоченный список событий прогона (план, вызовы инструментов, проверка), который видит пользователь |
| Роль | Читатель внутри компании: `cfo` (финансовый директор), `treasurer` (казначей), `owner` (собственник) |

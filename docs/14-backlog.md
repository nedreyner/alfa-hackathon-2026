# 14. Бэклог: план работ для агента-разработчика

## 1. Как работать с бэклогом

1. Берёшь первую задачу со статусом `[ ]`, у которой все зависимости `[x]`. Задачи `T0.*` выполняют люди. Если они не готовы, работай на синтетике и `LLM_MODE=fake` и не останавливайся.
2. Перед кодом читаешь разделы спецификации из строки «Спека». Имена, схемы, SQL, промпты и формулы берутся оттуда.
3. Для расчётных задач (ранжирование, проверка, профили) сначала пишешь golden-тесты из спецификации, потом код.
4. Задача закрыта, когда выполнены все пункты «Готово, когда» и Definition of Done из `CLAUDE.md`. Статус меняется в таблице §3 на `[x]`.
5. Живые вызовы LLM нужны только в критериях с пометкой **(live)**. Запускать их через CLI с `--max-cost`, а потраченную сумму записать в сообщение коммита.
6. Приоритеты: **P0** — без этого нет демо; **P1** — заметно усиливает решение; **P2** — если останется время. Минимальный срез (MVP) — все P0.

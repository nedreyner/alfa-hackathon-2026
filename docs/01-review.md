# 01. Разбор исходного плана и принятые решения

## 1. Итоговая оценка

У исходного плана верное ядро. В нём правильная целевая аудитория (115 компаний с выручкой от 15 млрд ₽), сильное отличие от других команд («цепная реакция» через граф платежей), честный слой доверия и простая инфраструктура без серверов БД. Как задание для разработки он недостаточен: не определены гранулярность отраслей, схема данных, формулы скоринга, протокол агента, поведение при сбоях и бюджет в цифрах. Если оставить как есть, разработчик примет эти решения на ходу, и они разойдутся между модулями.

Ниже перечислено, что оставляем, что меняем (в формате ADR) и какие риски закрываем.

## 2. Что оставляем без изменений

- **Фича A «Цепная реакция»** — главная. Опирается на данные кейса, которые другие команды, скорее всего, проигнорируют.
- **Фича B «Любая новость → инсайт»** — прямой ответ на проверку незнакомыми новостями (критерий 5).
- **Брифинг под роль (E)** и **слой доверия (F)** встроены в основу продукта, а не идут отдельными фичами.
- **Стек:** FastAPI, Pydantic v2, свой цикл агента на `openai` SDK, DuckDB и SQLite, BM25 с лемматизацией, React и `@alfalab/core-components`, SSE, docker compose.
- **Распределение моделей по задачам** с дешёвой моделью на массовую разметку и моделью другого семейства на проверку.
- **Кеш всех LLM-вызовов** и предварительный расчёт инсайтов для демо-компаний.

## 3. Решения (ADR)

| ID | Проблема в исходном плане | Решение | Где описано |
|---|---|---|---|
| ADR-01 | В рекомендации упомянута фича **C**, но в таблице её нет (D тоже) | Демо = **A + B**. C переопределена как «Что если» (чувствительность к ставке и курсу) с приоритетом **P2** | §5, `14-backlog.md` T5.3 |
| ADR-02 | Разметка «по разделам ОКВЭД» слишком грубая: раздел C объединяет всю обработку, G — всю торговлю. Пример «пошлины на металл → закупки у металлургов» на таком уровне не посчитать | Своя таксономия из **43 отраслей** с привязкой к префиксам ОКВЭД-2 (классы и группы). Опт разбит по видам товара: металлы, топливо, стройматериалы, продукты и т. д. | `03-data.md` §5.1 |
| ADR-03 | «Цепная реакция» молча предполагает, что отрасль известна у всех контрагентов | Отрасль контрагента берётся каскадом: ОКВЭД из таблицы компаний → ОКВЭД из платежей → ключевые слова в названии → `unknown`. Считаем **покрытие** и смешиваем фактические доли с типовыми долями отрасли пропорционально покрытию. Покрытие показываем в интерфейсе | `03-data.md` §6, `07-ranking.md` §5 |
| ADR-04 | Не определено направление платежей и чем мерить долю | Маппинг поддерживает обе схемы (плательщик/получатель или компания/контрагент + направление). Доля считается по сумме, при её отсутствии — по числу операций или связей | `03-data.md` §3.4 |
| ADR-05 | Скоринг задан словами («отрасль + контрагенты + факторы») | Формула с явными весами, noisy-OR по путям влияния, детерминированная матрица «канал × эффект → риск/возможность». Веса в `config/ranking.yaml` | `07-ranking.md` |
| ADR-06 | Полноценный агентный цикл на каждую пару «компания × событие» дорог, медленен и нестабилен | **Два режима** с общими компонентами. `pipeline`: фиксированный план → один вызов на черновик → проверка, для пакетного расчёта. `agentic`: динамический план и цикл с инструментами, для фичи B и по запросу. Оба пишут одинаковую трассу | `08-agent.md` §1 |
| ADR-07 | Неизвестно, поддерживают ли модели шлюза tools и `json_schema` | Финальный ответ отдаётся **инструментом `submit_insight`** (работает у любой модели с function calling). Резерв — `json_schema`, затем `json_object` со схемой в промпте и одна попытка починки. Возможности моделей измеряет `alfa llm probe` | `04-llm.md` §3, §5 |
| ADR-08 | Бюджет 500 ₽ в сутки не пересчитан в объёмы | Формула стоимости, приоритеты вызовов (`interactive` > `precompute` > `background`), резерв под интерактив, суточный лимит 450 ₽ с запасом, предварительный расчёт только для демо-компаний | `04-llm.md` §7 |
| ADR-09 | Одно событие публикуют 3–5 СМИ, и simhash дубликаты не склеит: тексты разные | Кластеризация новостей в **события**. Инсайт строится на пару «компания × событие», количество независимых источников повышает доверие | `06-ingestion-search.md` §9 |
| ADR-10 | RSS даёт сотни новостей в день, большинство нерелевантны, а разметка через LLM стоит денег | **Детерминированный префильтр** до LLM: рубрики источника, словари экономической лексики и отраслей, стоп-рубрики | `06-ingestion-search.md` §6 |
| ADR-11 | В SQLite FTS5 нет русской морфологии | Лемматизируем pymorphy3 **до** индексации и запроса. В FTS храним леммы | `06-ingestion-search.md` §13 |
| ADR-12 | PyMuPDF распространяется под **AGPL-3.0** | pdfplumber (MIT) для текста и таблиц, pypdfium2 (Apache/BSD) для рендера страниц в картинки для Qwen3-VL | `06-ingestion-search.md` §11 |
| ADR-13 | Фича B загружает произвольный URL: это SSRF | Безопасный загрузчик: только http/https, проверка IP после DNS (запрет частных, loopback и link-local адресов), повторная проверка на каждом редиректе, лимиты размера и времени | `11-security.md` §3 |
| ADR-14 | DuckDB не допускает записи из одного процесса при чтении из другого | DuckDB-файл собирается один раз (`init`), дальше `api` и `worker` открывают его только на чтение. Всё изменяемое (в том числе правки профиля) хранится в SQLite | `02-architecture.md` §7 |
| ADR-15 | SSE со стримингом шагов, а прогоны бывают и в `api`, и в `worker` | Трасса пишется в SQLite. SSE-эндпоинт опрашивает новые события раз в 250 мс и поддерживает `Last-Event-ID`. Брокер сообщений не нужен | `02-architecture.md` §7, `09-api.md` §5 |
| ADR-16 | «Нативная реклама» может выдумывать продукты банка | Каталог продуктов с правилами срабатывания (`config/products.yaml`). Агент выбирает только из переданных кандидатов, неизвестный `product_id` отбрасывается | `08-agent.md` §15 |
| ADR-17 | Слой доверия держится только на разметке LLM | Проверка в два слоя. Детерминированный: у каждого утверждения есть ссылки, ссылки существуют, **числа из утверждения есть в источнике**, признаки клиента существуют. LLM-судья другого семейства: подтверждено, частично, не подтверждено или противоречит. Явное правило прохождения и деградации | `08-agent.md` §9 |
| ADR-18 | Render free не даёт постоянного диска, а шлюз может быть доступен только из РФ | Основной вариант — VPS с Docker (российский, если шлюз этого требует). Railway — с volume. Запасной адрес шлюза задаётся в конфиге | `13-deploy-demo.md` §4 |
| ADR-19 | Демо зависит от живого шлюза | Режим `LLM_MODE=replay` и «заморозка» демо: кеш LLM-ответов демо-сценария экспортируется в `data/seed/` и воспроизводится без сети. Живыми остаются только незнакомые новости жюри | `04-llm.md` §9, `13-deploy-demo.md` §6 |
| ADR-20 | 40 пар «клиент × новость» мало для nDCG@5 | 6 демо-компаний × 10 событий = 60 суждений с градацией 0–3. LLM делает предразметку, человек её проверяет | `12-quality.md` §2 |
| ADR-21 | Реальные данные нельзя публиковать | Генератор синтетики с той же логической схемой и распределениями. Синтетика лежит в git, реальные данные — в `data/raw/` (gitignore). Профиль данных выбирается переменной `DATA_PROFILE` | `03-data.md` §8 |
| ADR-22 | Неизвестны формулировки 6 вопросов кейса | Явный маппинг блоков инсайта на вопросы (допущение A1), подписи в UI берутся из одного словаря | `08-agent.md` §8.3 |
| ADR-23 | «Пользователь видит только свою компанию» не подкреплено механизмом | Подписанная cookie-сессия с `company_id`. Инструменты агента получают компанию из контекста сервера, а не из аргументов LLM. Смена компании — это новый вход | `11-security.md` §2 |
| ADR-24 | Нет единого стандарта тестирования LLM-логики | `FakeLLM` — детерминированные эвристические ответы по задачам. Он позволяет прогнать всю систему офлайн и разрабатывать интерфейс без бюджета | `04-llm.md` §9 |

## 5. Состав фич и приоритеты

| Фича | Что входит | Приоритет |
|---|---|---|
| A. Цепная реакция | Пути влияния own/supply/demand/factor, доли из платежей, покрытие, граф на карточке, превью цепочки в ленте | **P0** |
| B. Любая новость → инсайт | URL или текст → разбор → поиск связи с компанией → инсайт; шаги видны вживую через SSE; цель — до 20 секунд | **P0** |
| F. Слой доверия | Метки fact/bank/ai у каждого утверждения, источник по клику, проверка, уровень уверенности | **P0** |
| Лента и карточка (6 блоков) | Ранжированная лента, карточка с 6 блоками, трасса «Как мы пришли к выводу» | **P0** |
| Позиция Альфа-Банка | Текст PDF, поиск, цитаты в блоке «Позиция банка» | **P0** (только текст), разбор графиков через VL — P2 |
| E. Брифинг под роль | Переключатель роли, «3 события за 60 секунд», действия под роль | **P1** |
| Чат «Спросить аналитика» | Уточнения в контексте инсайта, ответы с источниками | **P1** |
| Главная Альфа-Бизнеса (макет) | Счета, платежи, карточка «Сегодня важно для вас» | **P1** |
| «Что мы о вас знаем» | Профиль, признаки, контрагенты, правка данных | **P1** |
| Нативные продукты | Каталог, правила, «Оставить заявку» (имитация с подтверждением) | **P1** |
| Страница качества | Офлайн-метрики, онлайн-метрики, бюджет | **P1** |
| Живой сбор RSS | Расписание, полный текст, конвейер | **P1** (для демо хватает seed) |
| LLM-переранжирование | Переоценка 20 лучших событий моделью | **P2** |
| C. «Что если» | Ползунок ставки и курса → пересчёт чувствительности | **P2** |
| Цепочка второго уровня | Поставщики поставщиков | **P2** |
| Очередь экспертной проверки | Утвердить или отклонить инсайты с низкой уверенностью | **P2** |

**Минимальный срез (MVP)**, если время кончается: все P0, данные только синтетические, новости только из seed, демо через `replay`.

## 6. Реестр рисков

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Модель шлюза плохо держит JSON | Средняя | Высокое | ADR-07: `submit_insight` и стратегия починки; цепочка запасных моделей |
| Шлюз недоступен во время показа | Низкая | Критическое | ADR-19: replay-кеш, готовые инсайты; запасной адрес шлюза |
| Бюджет кончается в день показа | Средняя | Высокое | Резерв под интерактив, остановка фоновых задач, прогрев кеша накануне |
| Реальный CSV устроен иначе, чем ожидается | Высокая | Среднее | Маппинг колонок, `alfa data validate`, запасные режимы |
| Мало качественных новостей под истории демо-компаний | Средняя | Высокое | Seed собирается заранее под демо-компании; демо-истории подстраиваются под реальные новости |
| Фича B дольше 20 секунд | Средняя | Среднее | Шаги стримятся сразу; быстрые модели; параллельные инструменты; жёсткий таймаут 45 с |
| Галлюцинации в фактах | Средняя | Высокое | ADR-17, деградация: неподтверждённое удаляется, уверенность понижается |
| Ограничения хостинга (диск, сеть) | Средняя | Среднее | ADR-18, проверка развёртывания до полировки интерфейса |
